# 数据库表优化说明

本文档说明了数据库表结构的优化内容，以提高查询性能。

## 优化概述

本次优化主要为所有表添加了必要的索引，以提高常用查询的性能。索引优化遵循以下原则：

1. **为WHERE子句中经常使用的字段添加索引**
2. **为JOIN操作的关联字段添加索引**
3. **为ORDER BY和GROUP BY使用的字段添加索引**
4. **为经常用于过滤的状态字段添加索引**
5. **为关联表添加唯一联合索引，防止重复数据**

## 各表索引优化详情

### 1. AA01 (用户表)

**新增索引：**
- `AAA010` (状态) - 用于按状态筛选用户
- `AAA016` (创建人) - 用于查询创建人创建的用户
- `AAA017` (修改人) - 用于查询修改人修改的用户

**已有索引：**
- `AAA002` (邮箱) - 唯一索引 ✓
- `AAA003` (手机号) - 唯一索引 ✓
- `AAA013` (最后登录时间) - 索引 ✓

### 2. AA05 (角色表)

## 唯一联合索引

为了防止关联表出现重复数据，为以下表创建了唯一联合索引：

1. **AA07 (用户角色关联表)**: `uk_user_role` - 防止同一用户被重复分配同一角色
2. **AA12 (角色菜单关联表)**: `uk_role_menu` - 防止同一角色被重复分配同一菜单

## 性能提升预期

添加这些索引后，以下查询场景的性能将显著提升：

1. **用户列表查询**：按状态、创建人、修改人筛选
2. **权限列表查询**：按分类、状态筛选，按资源路径+方法查找
3. **菜单树查询**：按父菜单ID、菜单类型、状态筛选
4. **系统日志查询**：按用户ID、操作类型、日志级别、时间范围查询
5. **文件列表查询**：按创建人、存储类型、分类筛选
6. **关联查询**：用户角色、角色菜单关联查询

## 注意事项

1. **索引维护成本**：索引会占用额外的存储空间，并会在插入、更新、删除时增加维护成本。但考虑到查询性能的提升，这些成本是值得的。

2. **唯一联合索引**：唯一联合索引会在数据库迁移时自动创建，如果索引已存在则跳过。

3. **索引更新**：当表结构发生变化时，GORM的AutoMigrate会自动更新索引。

4. **生产环境**：在生产环境部署前，建议在测试环境验证索引创建是否成功，并监控查询性能。

## 验证索引创建

可以通过以下SQL查询验证索引是否创建成功：

### MySQL
```sql
-- 查看表的索引
SHOW INDEX FROM AA01;

-- 查看所有表的索引
SELECT 
    TABLE_NAME,
    INDEX_NAME,
    COLUMN_NAME,
    SEQ_IN_INDEX,
    NON_UNIQUE
FROM 
    information_schema.statistics
WHERE 
    TABLE_SCHEMA = DATABASE()
ORDER BY 
    TABLE_NAME, INDEX_NAME, SEQ_IN_INDEX;
```

### Oracle
```sql
-- 查看表的索引
SELECT 
    INDEX_NAME,
    COLUMN_NAME,
    COLUMN_POSITION
FROM 
    user_ind_columns
WHERE 
    TABLE_NAME = 'AA01'
ORDER BY 
    INDEX_NAME, COLUMN_POSITION;
```

## 后续优化建议

1. **定期分析表统计信息**：确保索引统计信息是最新的
2. **监控慢查询**：识别可能需要额外索引的查询
3. **分区表**：对于日志表等大表，考虑使用分区表
4. **归档策略**：对于历史数据，考虑归档到其他表或数据库
